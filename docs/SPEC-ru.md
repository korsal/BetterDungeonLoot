# ТЗ — BetterDungeonLoot («Улучшенный Лут в Подземельях»)

Внутренний документ (не шипается, docs/ помечается export-ignore).
Клиент: MoP Classic 5.5.4, Interface 50504.

## Проблема
В подземельях раздражает необходимость вручную роллить и подтверждать
каждую выпавшую вещь. Нужно автоматизировать рутину, но сохранить контроль
над реально нужными вещами и лут-этикет.

## Цели (по приоритету)
1. Скрыть подтверждение привязки BoP при ролле («станет персональной при поднятии»).
2. Убрать ролл-окно из центра экрана (мешает в бою) — перенести в настраиваемую точку.
3. Авто-Greed вещей, не подходящих классу по армор-типу.
4. Показывать в ролл-окне, кто из группы нажал Need (детект нинзя-лутинга).

## Функциональные требования

### F1. Авто-подтверждение привязки
- Ловить `CONFIRM_LOOT_ROLL(rollID, rollType)` → сразу `ConfirmLootRoll(rollID, rollType)`.
- Ловить `LOOT_BIND_CONFIRM(slot)` → `ConfirmLootSlot(slot)` (подбор BoP с трупа).
- Работает для любого ролла: авто-Greed аддона и ручного Need игрока.
- Настройка вкл/выкл (по умолчанию ВКЛ).

### F2. Перенос ролл-окна
- Перенести `GroupLootContainer` в настраиваемый якорь (по умолчанию — правый край,
  вне центра). Хук на `GroupLootContainer_Update`, чтобы позиция не сбрасывалась.
- Возможность перетащить мышью и запомнить позицию (SavedVariables).
- Настройка вкл/выкл (по умолчанию ВКЛ).

### F3. Умный авто-ролл
Режим по умолчанию для вещей — **Greed**. Логика при `START_LOOT_ROLL(rollID)`:
- Прочитать `GetLootRollItemInfo(rollID)` (canNeed/canGreed/canDisenchant, bindOnPickUp)
  и `GetLootRollItemLink(rollID)` → `GetItemInfo` (тип/подтип/слот).
- Определить категорию вещи:
  - **Телесная броня** (голова/плечи/грудь/запястья/кисти/пояс/ноги/ступни):
    - подтип == правильный для класса и уровня → «подходит»;
    - иначе → авто-**Greed**.
  - **Прочее** (плащ/кольцо/шея/тринкет/щит/фолиант/оружие, которое класс может носить):
    → считается «подходит» (общий режим).
  - **Совсем не usable** (`canNeed=false` и не носится) → **Greed**.
- Что делать с «подходящими» вещами — настройка:
  - `leave` (ПО УМОЛЧАНИЮ, подтверждено): НЕ роллить автоматически, оставить
    (перенесённое) окно открытым для ручного решения. Сохраняет этикет, детект
    нинзя осмыслен.
  - `need`: авто-Need на подходящие.
- Таблица армор-типов (порог 40 lvl):
  | Классы | < 40 | >= 40 |
  |---|---|---|
  | Warrior, Paladin, DeathKnight | Mail | Plate |
  | Hunter, Shaman | Leather | Mail |
  | Rogue, Druid, Monk | Leather | Leather |
  | Mage, Priest, Warlock | Cloth | Cloth |
- Исключения из правила армор-типа: плащ (INVTYPE_CLOAK), кольцо/шея/тринкет
  (Miscellaneous). Щиты/off-hand/оружие — по таблице usability класса (позже;
  на старте — «подходит», общий режим).
- Настройки: поведение для подходящих (leave/need); режим авто-грида
  (armor / cantuse / pawn). Разборка (disenchant) на этом билде MoP не поддержана —
  соответствующая опция удалена.

### F4. Показ Need-роллеров
- Через `C_LootHistory`: по `LOOT_HISTORY_ROLL_CHANGED(i, p)` читать `GetItem(i).rollID`,
  сматчить с `GroupLootFrame.rollID`, собрать игроков с `rollType == LOOT_ROLL_TYPE_NEED (1)`.
- Показать их имена (класс-цвет) строкой на/под соответствующим ролл-фреймом.
- Показывать ТОЛЬКО нажавших Need.
- Настройка вкл/выкл (по умолчанию ВКЛ).
- ЗАВИСИМОСТЬ: подтвердить в игре, что история обновляется вживую, а не только
  по завершении ролла.

### F6 (настройки + миникарта) — РЕАЛИЗОВАНО
- Кнопка у миникарты: ЛКМ — показать/скрыть окно, ПКМ — настройки; перетаскивается
  по кругу (db.minimapAngle).
- Панель настроек (Settings canvas, `/bdl config`):
  - ползунок строк 1..5 (db.rowCount);
  - ползунок истории 10..100 (db.storageMax);
  - режим авто-грида (radio): "cantuse" (гридить всё, что нельзя надеть/исп.,
    по canNeed) / "armor" (логика чужого армор-типа) / "pawn" (гридить всё, что
    не апгрейд по Pawn; показывается только если Pawn загружен);
  - галка авто-грид ресурсов (db.autoGreedResources): Gem(3)/Reagent(5)/TradeGoods(7);
  - галка полоски таймера на pending-роллах (db.showTimerBar).

## Область действия (scope)
По умолчанию — **инстансы (подземелья + рейды)**, в открытом мире не трогать
(подтверждено). Опции: только подземелья / подземелья+рейды / везде.
Определять через `IsInInstance()` → `"party"`/`"raid"`.

## Настройки / SavedVariables (BetterDungeonLootDB, account-wide)
- enabled (глобальный вкл/выкл)
- autoConfirmBind = true (F1)
- moveRollFrame = true; framePoint = {...} (F2)
- defaultRoll = "greed"; fittingBehavior = "leave"; enchanterDisenchant = false (F3)
- showNeeders = true (F4)
- scope = "instance" (party+raid)
- DB_VERSION + миграция при изменении схемы

## Слэш-команды
- `/bdl` — краткая справка / статус
- `/bdl config` — панель настроек (Settings canvas)
- `/bdl move` — разблокировать перенос ролл-окна
- (dev) `/bdl probe` — разовый дамп API для верификации

## Статус реализации
- F1 (авто-подтверждение привязки) — ГОТОВО, проверено в игре.
- F2 (перенос ролл-окна) — ЗАМЕНЕНО на F5. Стандартные ролл-окна Blizzard
  теперь скрываются (`hideBlizzardRoll`), роллим из окна-лога. Код F2 удалён.
- F5 (окно-лог лута) — РЕАЛИЗОВАНО, ждёт проверки в игре.
  Заменяет ролл-окна Blizzard (скрываются всегда); последние N=5 роллов;
  кнопки Need/Greed/DE/Pass прямо в окне; строка "You:" (что нагридил аддон),
  "Need:" (нинзя), "Won:"; таймер; перетаскивание; крестик прячет, /bdl log показ.
  Галка "Auto-greed" в шапке = db.autoRoll (синхр. с /bdl autoroll).
  Поведение: подходящая вещь (нужен ручной ролл, action=leave) АВТО-ОТКРЫВАЕТ
  окно; авто-гриженные пишутся тихо (окно не всплывает). Если Auto-greed выключен
  — каждая вещь открывает окно с кнопками (полностью ручной режим).
  Вёрстка строки (узкое окно 300px):
  - нужно ролить: под названием — классические иконки Need(кубик)/Greed(монета)/
    Pass(отмена) + DE если доступно;
  - ролл идёт/сделан: под названием — кружки цвета класса с иконкой выбора внутри,
    корона над победителем, 3-4 буквы ника (UTF-8-safe) под кружком.
    Кружок = WHITE8X8 + tint классом + CircleMaskScalable (pcall-guard).
- F3 (умный авто-Greed) — РЕАЛИЗОВАНО, ждёт проверки в игре.
  Сигнатура подтверждена: GetLootRollItemInfo -> texture, name, count, quality,
  bindOnPickUp, canNeed, canGreed, canDisenchant, reasonN/G/DE, deSkillRequired.
  Консервативно: авто-Greed ТОЛЬКО для телесной брони чужого армор-типа;
  всё прочее (подходящее/оружие/украшения/плащи/некэш) — leave.
  Армор-тип берём из classID/subclassID GetItemInfo (локалебезопасно).
- F4 (показ Need-роллеров) — РЕАЛИЗОВАНО, ждёт проверки в игре.
  Подтверждено пробником: `GetPlayerInfo` -> name, class, rollType, roll, isWinner, isMe;
  `GetItem` -> rollID, itemLink, numPlayers, isDone, winnerIdx, ...;
  rollType 0=pass, 1=need, 2=greed, 3=disenchant.

## Открытые вопросы (для верификации пробником в игре)
1. Живость `C_LootHistory` на 5.5.4 (F4) — обновляется ли по ходу ролла.
2. ~~Имя контейнера ролл-фреймов~~ — РЕШЕНО: `GroupLootContainer` есть.
3. Точная сигнатура `GetLootRollItemInfo` на 5.5.4 (F3).

Решённые дефолты: scope = инстансы (подземелья + рейды); поведение для
подходящих вещей = leave (оставлять окно, решает игрок).
